## 1. 반복문 대신 배열 전체 연산

NumPy/PyTorch 에서는 `for` 로 원소를 하나씩 처리하기보다 **배열(텐서) 전체에 한 번에 연산**하는 것이 훨씬 빠르고(C/CUDA 에서 실행) 코드도 짧습니다.

```python
# 느림
out = torch.empty(len(x))
for i in range(len(x)):
    out[i] = x[i] * 2 + 1

# 빠름
out = x * 2 + 1
```

## 2. 자주 쓰는 생성/누적 함수

| 함수 | 설명 | 예 |
|------|------|----|
| `torch.arange(n)` | `0 ~ n-1` 정수 텐서 생성 (`range` 의 텐서판) | `torch.arange(5)` → `[0, 1, 2, 3, 4]` |
| `torch.arange(a, b, step)` | 범위와 간격 지정 | `torch.arange(0, 1, 0.25)` → `[0, .25, .5, .75]` |
| `torch.linspace(a, b, n)` | 구간을 n 등분 | 시간 축, 주파수 축 만들기 |
| `torch.cumsum(x, dim)` | 누적 합이 필요할 때 | `torch.cumsum(torch.tensor([1, 2, 3]), 0)` → `[1, 3, 6]` |
| `torch.zeros / ones / randn(shape)` | 초기화 | `torch.randn(32, 1, 48000)` (테스트용 가짜 배치) |

> 철자 주의: `arange` (array + range) 입니다. `arrange` 가 아닙니다.

## 3. 의미 없는 차원 제거: `squeeze`

PyTorch 에서는 텐서 차원이 꼬이기 쉽습니다. DataLoader 를 거친 오디오 배치를 예로 들면:

```
[32, 1, 48000]   ← 32곡, 채널 1개(모노), 48000 샘플
```

여기서 `1` 은 사실상 의미가 없습니다. 이대로 Mel 변환을 하면 그 `1` 이 그대로 따라옵니다.

```
[32, 1, 48000] ──mel──▶ [32, 1, 80, 47]     ← 여전히 의미 없는 1
```

Mel 변환 **전에** `squeeze` 로 없애면 깔끔해집니다.

```
[32, 1, 48000] ──squeeze(1)──▶ [32, 48000] ──mel──▶ [32, 80, 47]
```

```python
x = x.squeeze(1)      # 1번 차원(크기 1)만 제거
```

> **꼭 차원 번호를 지정하세요.** `x.squeeze()` 는 크기가 1인 **모든** 차원을 지웁니다. 마지막 배치 크기가 1이면 배치 차원까지 사라져 `[48000]` 이 되는 버그가 생깁니다.
> 반대로 차원을 추가할 때는 `x.unsqueeze(dim)` 을 씁니다.

## 4. 배치 차원을 따라가며 설계하기 (예: 장르 분류기)

**학습은 배치 단위로 합니다.** 데이터셋에서 샘플을 하나씩 꺼내 batch size 만큼 쌓습니다. 이하 배치 크기 32, 샘플 하나의 Mel 결과는 `80 × 47` 이라고 가정합니다.

- `80` = 주파수 빈(frequency bin) 수 (`n_mels=80`)
- `47` = 시간 슬롯(time frame) 수 (48000 샘플, `hop_length=1024`일 때 `48000 // 1024 + 1 = 47`)

### 단계별 shape

| 단계 | 연산 | 샘플 1개 | 배치 전체 |
|------|------|----------|-----------|
| 0 | DataLoader 출력 | `1 × 48000` | `[32, 1, 48000]` |
| 1 | `squeeze(1)` | `48000` | `[32, 48000]` |
| 2 | MelSpectrogram | `80 × 47` | `[32, 80, 47]` |
| 3 | `transpose(1, 2)` | `47 × 80` | `[32, 47, 80]` |
| 4 | `Linear(80, 32)` | `47 × 32` | `[32, 47, 32]` |
| 5 | `Linear(32, 32)` | `47 × 32` | `[32, 47, 32]` |
| 6 | `flatten(1)` | `1504` (=47×32) | `[32, 1504]` |
| 7 | `Linear(1504, 10)` | `10` | `[32, 10]` ← 32곡 × 10장르 점수 |

### 왜 transpose 가 필요한가

`nn.Linear` 는 **마지막 차원**에만 적용됩니다. 주파수 80개를 입력으로 받아 32개 특징으로 바꾸는 층(`80 × 32` 행렬)을 쓰려면, 주파수 축이 마지막에 와야 합니다.

```
입력 47 × 80  @  층 80 × 32  =  출력 47 × 32     (샘플 1개 기준)
```

즉, 47개 시간 슬롯 각각에 **같은** `80 × 32` 행렬을 곱합니다.

> 혼동 주의: 이 층의 출력 차원 32는 배치 크기 32와 **우연히 같은 숫자일 뿐** 서로 관계가 없습니다. 실제 코드에서는 서로 다른 숫자(예: hidden=64)를 써 두면 shape 디버깅이 훨씬 쉽습니다.

### flatten 후 분류

`47 × 32 = 1504` 를 한 줄로 펴서 `1504 × 10` 층을 통과시키면 샘플마다 10개 카테고리 점수가 나옵니다. 배치 전체로는 `[32, 10]` 입니다.

```python
x = x.flatten(start_dim=1)   # 배치 차원(0)은 유지하고 나머지만 펴기 → [32, 1504]
```

> `flatten()` 을 인자 없이 쓰면 배치 차원까지 펴져 `[48128]` 이 됩니다. 반드시 `start_dim=1` 을 쓰세요.

이 출력은 아직 확률이 아닌 **logit** 입니다 → [출력 · 확률 · 손실](04-logits-probs-loss.md)

## 5. shape 디버깅 요령

```python
x = torch.randn(32, 1, 48000)   # 가짜 배치로 먼저 확인
print(x.shape)                  # 각 단계마다 출력
assert x.shape == (32, 1, 48000), x.shape
```

- 실제 데이터를 붙이기 전에 `torch.randn` 으로 만든 가짜 배치로 모델 전체 shape 를 먼저 확인하세요.
- `view` 는 메모리가 연속(contiguous)일 때만 동작합니다. transpose 다음에는 `reshape` 를 쓰는 것이 안전합니다.

| 함수 | 용도 |
|------|------|
| `squeeze(d)` / `unsqueeze(d)` | 크기 1 차원 제거 / 추가 |
| `transpose(a, b)` | 두 차원 교환 |
| `permute(...)` | 여러 차원 순서 재배치 |
| `reshape(...)` / `view(...)` | 모양 변경 (원소 수 동일) |
| `flatten(start_dim)` | 지정 차원부터 펴기 |
| `stack(list, dim)` | 같은 shape 텐서들을 새 차원으로 쌓기 (DataLoader 가 하는 일) |
| `cat(list, dim)` | 기존 차원을 따라 이어 붙이기 |
